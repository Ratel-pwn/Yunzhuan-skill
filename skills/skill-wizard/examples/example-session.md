# 示例对话：创建一个"设计文档生成"的 Skill

以下是一个完整的对话示例，展示 Skill Wizard 如何引导用户从零创建 Skill。

---

## 阶段 0：去重检查（静默）

AI 扫描 `skills/` 目录，发现已有 `turn-idea-into-spec`，功能高度相似。

**AI：** 我在仓库里发现了一个已有的 `turn-idea-into-spec` Skill，它已经覆盖了 PRD + 技术设计文档的生成。但它缺少几个你提到的关键点：项目上下文感知、全程对话驱动。你想怎么处理？

（提供选择题：在它基础上改造 / 从零新建 / 直接改进已有的）

**用户：** 新建一个。

---

## 阶段 1：理解意图 + 定义边界

**用户：** 我想做一个 skill，作为 PM/TM 的身份，帮助用户验证想法进行落地，并且产出完整的设计文档作为后续开发指导。

**AI：** 好的，方向很清楚。让我用几个选择题来确认关键细节：

（使用 AskUserQuestion，一次提供 4 个选择题）

1. 「验证想法」这个环节，Skill 主要做什么？
   - 结构化提问（通过引导问题帮用户拆解需求）
   - 全面分析（可行性分析 + 竞品调研 + 技术风险评估）
   - 轻量验证（快速过一遍核心假设 + 利弊分析）

2. 设计文档产出到什么级别？
   - PRD 为主
   - PRD + 技术设计（一站式搞定）
   - 技术设计为主

3. 主要面向谁使用？
   - 开发人员
   - PM/产品人员
   - 所有角色通用

4. Skill 指令语言用中文还是英文？
   - 中文
   - 英文

**用户：** （选择了选项，并在第 1 题补充了自定义回答：需要根据项目目录状态自动适配）

**AI：** 收到，还有两个小问题：

（再用一轮 AskUserQuestion）

1. 设计文档最终输出成什么格式？
   - Markdown 文件（保存到 docs/）
   - 直接输出到对话
   - 两者都支持（推荐）

2. Skill 名字我建议叫 `idea-to-design`，OK 吗？
   - idea-to-design
   - validate-and-design
   - product-architect

**用户：** 两者都支持，名字就叫 idea-to-design。

**AI：** 好的，让我确认一下理解：
- 任务：以 PM/TM 身份，通过对话引导用户验证想法并产出设计文档
- 触发场景：用户有想法/需求想要落地时
- 核心逻辑：感知项目上下文 → 结构化提问引导 → 产出 PRD + 技术设计
- 输入：用户的想法描述 + 项目上下文（自动检测）
- 输出：Markdown 设计文档（文件 + 对话摘要）
- 指令语言：英文

这样理解对吗？

**用户：** PRD 和技术设计文档的产出过程也要通过提问来引导用户，帮助梳理想法。

**AI：** 明白，全程对话驱动——文档是对话的产物，不是闷头写出来的。我把这个作为核心原则加进去。

---

## 阶段 3：起草

AI 生成 SKILL.md 并展示完整内容，包含：
- Phase 0: 项目上下文检测
- Phase 1-4: 全程对话驱动的 4 阶段流程
- 设计文档模板
- 边界说明

同时展示质量自检清单通过情况：8/8 全部通过。

---

## 阶段 4：验证

**AI：** 要试运行几个测试场景吗？

**用户：** 先这样，我后面自己验证。

---

## 阶段 5：交付

**AI：** 你打算把 idea-to-design 安装到哪里使用？

（提供选择题：全局安装 / 留在仓库里 / 我自己处理）

**用户：** 我自己处理。

**AI：**
```
你的 Skill「idea-to-design」已经创建好了！

- 位置：skills/idea-to-design/
- 触发方式：idea、design doc、PRD、technical spec、validate concept 等
- 包含文件：SKILL.md, README.md, examples/example-session.md
- 质量检查：8/8 项全部通过
```

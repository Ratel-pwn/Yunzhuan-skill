# turn-idea-into-spec

一句话说明：以 PM/TM 视角把想法验证并落地，输出可开发的 PRD/技术设计文档与交付计划。

## 何时使用

- 想验证一个产品/功能想法是否值得做（需要假设与验证计划）
- 需要把需求写成研发可直接开工的 PRD / 设计文档 / tech spec
- 需要拆解任务、排期、里程碑、风险与上线计划

## 使用方式

直接描述你的目标与约束，推荐包含：

- 你要解决的问题（现状与痛点）
- 目标用户与使用场景
- 你已有的事实/数据/原型链接（如果有）
- 约束：截止时间、平台、团队规模、合规/安全要求、依赖系统
- 希望输出：单文件 `design-doc.md` 还是多文件（不选则默认单文件）

## 输入/输出

- 输入：
  - 一段需求/想法描述（越具体越好）
  -（可选）现有系统信息、接口/数据、原型、竞品、历史方案
- 输出（默认 Markdown）：
  - 需求与验收（FR + AC）
  - 用户流程（含异常/边界）
  - 技术方案与权衡、数据模型、API/事件、权限
  - NFR（性能/可靠性/安全/可观测性）
  - 测试/发布/灰度/回滚计划
  - 里程碑与 Backlog（Epic/Story/Task）

## 依赖与权限

- 依赖：无（纯文本交付）
- 权限：
  - 文件系统：默认不写入；仅在用户同意后生成到指定目录
  - 网络：默认不访问外网；如需竞品/资料调研，先征得用户同意
  - 命令执行：默认不执行命令
